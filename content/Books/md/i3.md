# Расширенные возможности Markdown

Здесь собрано то, что выходит за рамки базового синтаксиса. Часть функций зависит от движка форума (GitHub-flavored Markdown, CommonMark, Markdown Extra). Если что-то не работает — уточните у администрации, какой парсер используется.

---

## Таблицы

Таблицы рисуются «решёткой» из вертикальных черт `|` и дефисов `-`. Дефисы задают выравнивание.

```
| Слева      | По центру | Справа    |
|:-----------|:---------:|----------:|
| текст      | текст     | текст     |
| ещё текст  | ещё       | ещё       |
```

Отобразится:

| Слева | По центру | Справа |
|:---|:---:|---:|
| текст | текст | текст |
| ещё текст | ещё | ещё |

**Правила:**
* Двоеточие слева `:---` — выравнивание по левому краю.
* Двоеточия с обеих сторон `:---:` — по центру.
* Двоеточие справа `---:` — по правому краю.
* Количество дефисов не важно — хотя бы один.
* Внешние вертикальные черты необязательны, но с ними читабельнее.

## Сноски

Сноска — это ссылка на пояснение внизу документа. Удобно для каталогов и научных текстов.

```
Шахин-Гирей правил с 1777 по 1783 год.[^1]

[^1]: Здесь можно дать полное пояснение, источник или примечание.
```

Отобразится так: Шахин-Гирей правил с 1777 по 1783 год.[^1]

[^1]: Здесь можно дать полное пояснение, источник или примечание.

## Блоки кода с подсветкой синтаксиса

После трёх открывающих обратных кавычек укажите язык — и код подсветится:

```python
def hello(name):
    print(f"Привет, {name}")
```


Популярные языки: `python`, `js`, `bash`, `json`, `html`, `css`, `sql`, `yaml`.

## Вложенные списки

Отступ в **2 или 4 пробела** создаёт вложенность:

```
1. Первый уровень
   * Второй уровень
     * Третий уровень
2. Второй пункт первого уровня
```

Отобразится:

1. Первый уровень
   * Второй уровень
     * Третий уровень
2. Второй пункт первого уровня

## Экранирование символов

Если нужно показать символ как есть (например, звёздочку), поставьте перед ним `\`:

```
\*не курсив\*
```

Отобразится: \*не курсив\*

Полный список символов, требующих экранирования:
`\` `` ` `` `*` `_` `{` `}` `[` `]` `(` `)` `#` `+` `-` `.` `!` `|` `>`

## Автоматические ссылки

Обрамляйте URL угловыми скобками — и он станет ссылкой, даже если внутри есть спецсимволы:

```
<https://example.com/путь/с_подчёркиванием>
```

## HTML внутри Markdown

Многие парсеры разрешают вставлять HTML напрямую. Это полезно для того, чего нет в самом Markdown:

```html
<details>
  <summary>Спойлер: нажмите, чтобы раскрыть</summary>
  Здесь может быть длинный текст, таблица или картинка.
</details>
```

Отобразится как раскрывающийся блок (если форум поддерживает):

<details>
  <summary>Спойлер: нажмите, чтобы раскрыть</summary>
  Здесь может быть длинный текст, таблица или картинка.
</details>

Другие полезные HTML-теги:
* `<br>` — принудительный перенос строки.
* `<sub>текст</sub>` — нижний индекс.
* `<sup>текст</sup>` — верхний индекс.
* `<kbd>Ctrl</kbd>+<kbd>S</kbd>` — обозначение клавиш: <kbd>Ctrl</kbd>+<kbd>S</kbd>.

## Ссылки-сноски (reference links)

Если одну и ту же ссылку нужно использовать многократно, удобно вынести её в конец документа:

```
Первая ссылка на [каталог][cat].
Вторая ссылка на тот же [каталог][cat].

[cat]: https://example.com/catalog
```

Отобразится: Первая ссылка на [каталог][cat]. Вторая ссылка на тот же [каталог][cat].

[cat]: https://example.com/catalog

---

## Вставка видео и embed-контента

Сам Markdown видео не поддерживает. Варианты:

1. **Готовая ссылка-превью** (например, с YouTube): просто вставьте URL — многие форумы сами развернут плеер.
2. **HTML-тег `<iframe>`** — если форум разрешает:

```html
<iframe width="560" height="315" src="https://www.youtube.com/embed/VIDEO_ID"></iframe>
```

## Математические формулы (LaTeX)

Поддерживается на GitHub, в Obsidian, в некоторых форумах. Обрамление — знак доллара:

```
Стоимость $C = \frac{m \cdot p}{100}$, где $m$ — масса, $p$ — проба.
```

Отобразится: Стоимость $C = \frac{m \cdot p}{100}$, где $m$ — масса, $p$ — проба.

Для блочной формулы — двойные доллары:

```
$$
E = mc^2
$$
```

## Содержание с автоматическими ссылками

На GitHub и в многих вики-движках заголовки автоматически получают якоря. Ссылку на них можно сделать так:

```
[Перейти к разделу «Таблицы»](#таблицы)
```

Правило формирования якоря: заголовок в нижнем регистре, пробелы заменены дефисами, знаки препинания удалены.

## Чего нет в Markdown (и не появится)

* **Цвет текста.** Не поддерживается намеренно.
* **Размер шрифта.** Тоже нет.
* **Выравнивание абзаца** (кроме таблиц). Только через HTML, если разрешён.
* **Шрифты.** Markdown не управляет гарнитурой — это задача CSS форума.

Если очень нужно — используйте HTML, но помните: **это ломает переносимость**. Текст, написанный «чистым» Markdown, одинаково хорошо выглядит везде — на GitHub, в Obsidian, в Telegram, на любом форуме. Как только вы добавляете HTML, вы привязываете себя к конкретной платформе.

---

## Полезные привычки

1. **Пишите с пустой строкой между блоками.** Markdown чувствителен к «прилипанию» — цитата, прилипшая к абзацу, перестанет быть цитатой.
2. **Проверяйте предпросмотром.** Всегда. Даже опытные пользователи.
3. **Не злоупотребляйте выделением.** Если всё жирное — значит, ничего не жирное.
4. **Структура важнее украшений.** Заголовки, списки и пустые строки делают текст читаемым лучше, чем любая подсветка.
5. **Используйте таблицы для каталогов.** Markdown отлично работает как «лёгкая база данных» — таблицы + сноски + ссылки.
