# Настройки, тарифы лимиты. уже есть два модуля в системе для этого, но я хотел бы переделать и возможно сделать все в одном модуле.

- Сервис служит для работы с настройками системы (всех сервисов имеющих такие настройки), как общих так и тарифицируемых в одном месте системы
- Есть как свой API так и свой UI

- Система состоит из нескольких сервисов. Каждый сервис имеет свой собственный набор переменных которые характеризуют работу сервиса.

Пример:
```
  Сервис регистрации/авторизации:
    - срок действия инвайта
    ...
  Сервис форум:
    - Окно редактирования поста/комментария (минуты) (0 — редактирование запрещено, -1 — без ограничения по времени, положительное число — сколько минут после публикации можно править свой текст.)
    - Окно смены +/- голоса (минуты) (Ключ forum.vote.changeWindowMinutes. С момента первого голоса: 0 — нельзя менять, -1 — всегда, иначе N минут (сменить +↔− или снять).)
    - Максимальное количество вложений
    - Максимальный размер файла вложения
    - Лимит постов
    - Лимит комментов
  Сервис аукцион:
    - Соотношение сторон кадра при загрузке. Пиксели отображения — через imgproxy. Ширина (aspectWidth)
    - Соотношение сторон кадра при загрузке. Пиксели отображения — через imgproxy. Высота (aspectHeight)
    ...
  Сервис чат
    - Spawn: max копируемой истории
    - Окно правки сообщения (мин)
    - Окно удаления своего сообщения (мин)
    - Жёсткий max длины сообщения
    - Размер страницы истории (подгрузка)
```


Нужен универсальный сервис управления этими настройками и тарифами.

Зарание неизвесно какие именно настройки и каких сервисов будут тарифицироватся.

Любой сервис при старте регистрирует свои настройки в нашем сервисе настроек тарифов. При регистрации пареметра сервис передаёт
  - сервис (auction, chat, forum, ...)
  - наименование параметра (auction.lot.image.aspectHeight, auction.lot.image.aspectWidth, chat.group.leaveKeepsHistory, chat.message.lengthHardMax, ...)
  - описание назначения параметра, дескрипшин
  - категория параметра: (
    -  [значение для конкретного пользователя через выбранный тариф],
    - limited-user-var [значение, остаток доступных использованей для конкретного пользователя, использует внутренние счетчики, обновляет/выставляет заданное для периода лимита значение из тарифа. для одного значения может быть несколько лимитов в разных периодах, к примеру лимит на создание постов - (1 - в час, 3 - в сутки, 5 - в неделю, 10 - в месяц), все расчеты лимитов идут относительно даты активации тарифа], при нескольких лимитах на значение (час, сутки, месяц) проверка ведется в каждом периоде и все периоды должны дать положительный остаток для выполнения лимитированной операции.
  - тип параметра (boolean, int, enum, string, ...)
  - опции параметра (min, max) для числа. доступные enum для enum., и.т.д.
  - значение по умолчанию или список период/значение 
  - цена покупки единицы лимита для использования в случае расхода лимитов. Значение цены может быть разным у разных тарифов. 


Сервис имеет линейный справочник "Тариф", поля: 
  - наименование, 
  - описание, 
  - цена месяц, 
  - цена год.
Доступные периоды (час, сутки, неделя, месяц)
ведется логирование использований всех лимитированных действий для дальнейшего изучения и корректировки.
Значения записываются в зависимости от категории параметра
system-var одно значение параметра на сервис
tarif-var одно значение на пересечении параметра сервиса и тарифа
limited-user-var одно значение на пересечении параметра сервиса, тарифа и периода, значения которые восстанавливаются при завершении цикла периода (крон задача которая каждый минимальный период вызывается и контралирует концы циклов существующих периодов и обновляет лимиты в законченных циклах).
